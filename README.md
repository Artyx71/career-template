# Career Template

Локальный центр поиска работы: отправленные отклики, статусы, переписка, сопроводительные письма, версии резюме, заметки и напоминания. Интерфейс на русском, время — Москва.

## Запуск

Нужен Python 3.11+; для основной работы сторонних пакетов нет.

```bash
./start.sh
```

Открыть http://127.0.0.1:4317. Если порт занят, запустите `./start.sh --port 4318` и откройте http://127.0.0.1:4318.

Мониторинг работает, пока запущен дашборд. Для HH и Telegram Web нужны отдельные браузеры с действующими сессиями. После пробуждения компьютера проверки продолжатся.

Сервер слушает только `127.0.0.1`. При первом запуске создаётся пустая локальная база. Gmail, HH и Telegram подключаются отдельно к вашим аккаунтам.

- Источники: `~/Documents/Career-template/`, все вложенные папки с журналами.
- База, настройки и локальный профиль HH: `~/.local/share/career-template/`.
- Настройка путей: `CAREER_SOURCE_DIR`, `CAREER_DATA_DIR`.
- Для раздела «Мои резюме» положите PDF в `~/Documents/Career-template/resumes/` (или в `resumes/` внутри заданного `CAREER_SOURCE_DIR`).
- Все изменения заметок и статусов сохраняются в SQLite, а не в памяти браузера.

## Что обновляется автоматически

Каждые 30 секунд сервер импортирует изменившиеся `*-applications.jsonl`, очереди и исследования вакансий. Страница запрашивает актуальные данные каждые 5 секунд. Один отклик определяется сочетанием площадки и ID вакансии: повторное событие или дополнение письма не увеличивает счётчик.

Кнопка ↻ рядом с HH читает статусы и прокручивает страницы откликов в авторизованном браузере, затем читает доступные чаты. Переключатель включает этот проход каждые 2 часа, пока работает сервер. Один проход HH может работать до 2 часов. Пока он идёт, повторная проверка HH не запускается. Фоновая проверка использует отдельную временную вкладку, не переключает активную вкладку и не отправляет сообщения, отклики или платные действия.

Для синхронизации HH нужен Node.js, Playwright и браузер с CDP по `http://127.0.0.1:9222`. Поддерживается текущая сессия Chromium. Установите локальные зависимости из корня проекта командой `npm ci`. Для уже установленного пакета можно задать `PLAYWRIGHT_MODULE`. Адрес подключения меняется через `CAREER_CDP_URL`. Если браузер закрыт, сессия истекла или HH изменил страницу, показывается ошибка, предыдущие данные сохраняются. Капча не обходится.

## Входящие

Раздел «Входящие» показывает Gmail и изменения в HH. Фильтр «Требуют действий» поднимает срочные сообщения, задачи и напоминания. Откройте карточку, чтобы увидеть оригинальный диалог, изменить классификацию, сохранить следующий шаг, дедлайн или время интервью по Москве и локальный черновик. Ручные статусы откликов имеют приоритет. Рассылка остаётся на паузе.

### Gmail

1. В [Google Cloud Console](https://console.cloud.google.com/) включите Gmail API и создайте OAuth client ID типа **Desktop app**. Если приложение в режиме Testing, добавьте свой аккаунт в тестовые пользователи. Скачайте JSON клиента в каталог вне репозитория.
2. В Gmail создайте отдельный ярлык `Career` и отметьте им карьерные диалоги. Подходящие уведомления других площадок можно помечать правилами Gmail по известным отправителям. Имя своего ярлыка задайте через `CAREER_GMAIL_LABEL` для запуска дашборда и для команд агента.
3. Запустите `python3 manage.py gmail-auth --client /путь/к/файлу.json --account ваш-адрес` на том же компьютере, где открыт браузер. Откройте выведенную ссылку и подтвердите доступ. Команда проверит выбранный аккаунт, прежде чем заменить локальную авторизацию. При её отзыве или истечении срока повторите эту команду. [Документация Google OAuth для Desktop app](https://developers.google.com/identity/protocols/oauth2/native-app).
4. Запустите `./start.sh` или нажмите «Проверить Gmail» в уже работающем дашборде. Первая синхронизация читает переписку по ярлыку. Дальше сервер проверяет Gmail каждые 2 часа по курсору History API. При истечении срока курсора он перечитывает только помеченные диалоги. [Документация Gmail History API](https://developers.google.com/workspace/gmail/api/guides/sync).

Разрешение `gmail.readonly` даёт техническую возможность читать почтовый ящик. Приложение запрашивает тексты только в помеченных карьерных диалогах. OAuth хранится в `${XDG_CONFIG_HOME:-~/.config}/career-template/gmail-credentials.json` с правами `600`. Черновики хранятся в SQLite и не меняют Gmail. Входящее письмо с точной ссылкой на одну известную вакансию может обновить её автоматический статус.

### HH

Для штатного входа откройте выделенный локальный профиль, чтобы синхронизация не зависела от основной сессии Chromium.

```bash
chromium --user-data-dir="$HOME/.local/share/career-template/hh-browser" \
  --remote-debugging-address=127.0.0.1 --remote-debugging-port=9222 https://hh.ru/applicant/negotiations
```

Войдите на HH в этом окне, нажмите ↻ в дашборде и при необходимости включите проверку каждые 2 часа. Встреча считается назначенной после ручного подтверждения. Если HH не показывает автора или время сообщения, дашборд предлагает открыть оригинал. Подтверждение API-доступа потребовало бы OAuth для аккаунта и приложения HH. [Документация HH API](https://api.hh.ru/openapi/redoc).

### Черновики и Telegram

В Codex откройте репозиторий и попросите подготовить черновик для выбранной записи. `python3 manage.py inbox` показывает ID, `python3 manage.py inbox-context ID` возвращает текущий контекст выбранного Gmail-диалога и адрес получателя ответа. `python3 manage.py inbox-draft ID --file -` сохраняет черновик из stdin через работающий дашборд. Для HH агент сверяет переписку и адресата по ссылке на оригинал.

Для уведомлений создайте своего бота через BotFather и напишите ему `/start` в личном чате. Узнайте числовой ID этого чата из `message.chat.id` в ответе метода `getUpdates` вашего бота. Храните токен локально. Создайте `${XDG_CONFIG_HOME:-~/.config}/career-template/telegram-credentials.json` с правами `600` и двумя полями `"token"` и `"chat_id"`. Если Telegram доступен через локальный HTTP-прокси, добавьте поле `"proxy"` с адресом вида `http://127.0.0.1:2080`. Сервер проверяет очередь каждые 30 секунд. Уведомление содержит только общее напоминание, без ссылок, адресов и текста переписки. [Документация Telegram Bot API](https://core.telegram.org/bots/api#sendmessage).

Для опциональной проверки рабочей папки Telegram откройте отдельный браузер:

```bash
chromium --user-data-dir="$HOME/.local/share/career-template/telegram-browser" \
  --remote-debugging-address=127.0.0.1 --remote-debugging-port=9224 https://web.telegram.org/k/
```

Для авторизованной сессии Telegram Web с CDP на `127.0.0.1:9224` можно добавить в тот же файл `"watch_folder": {"id": 1, "name": "Рекрутеры"}`. Подставьте ID и точное имя своей рабочей папки. Каждые два часа дашборд проверяет непрочитанные счётчики только этой папки, не открывая диалоги. Первый проход показывает текущие непрочитанные чаты и сохраняет базовый снимок. Дальше бот уведомляет об изменениях. В карточке доступна ссылка на чат, текст переписки из Telegram не копируется.

При запуске сервера и затем каждые два часа по завершении проверок бот отправляет сводку даже при отсутствии новых сообщений. В ней счётчики дашборда, число записей «Нужны действия» и результат по каждому источнику. Уведомления других площадок, помеченные ярлыком `Career`, входят в строку Gmail. Отдельные напоминания о новых событиях и дедлайнах продолжают работать.

## Как читать счётчики

- **Всего откликов**: записи с подтверждённой отправкой, ранее существовавшие отклики и обнаруженные в личном кабинете HH. Неподтверждённые отправки исключены.
- **Новых отправок**: в журнале есть действие `sent`. `already_sent` учитывается отдельно, точная дата отправки ему не приписывается.
- **Сегодня**: новые отправки с известной датой, с полуночи по Москве. У откликов, впервые найденных на HH, дата может быть неизвестна — они не прибавляются к сегодняшнему результату.
- **Ошибка доставки** (`delivery_failed`) исключает письмо из откликов, сохраняя историю попытки. Подтверждённая повторная отправка после ошибки учитывается один раз, с новой датой.
- **Прямые обращения рекрутерам** (`recruiter_contacted`, тип `recruiter_outreach`) сохраняют дату, письмо и следующий шаг, но не увеличивают счётчики вакансий. Они доступны в «Следующих шагах» и очереди.
- **Приглашение**: метка HH «Собеседование»/«Приглашение», включая запрос анкеты. Это не назначенная встреча. Встречу отмечают вручную, когда согласованы время и формат.
- **Ручной статус** имеет приоритет над автоматическим. Выбрать «Автоматически», чтобы снова следовать статусу площадки.
- **Очередь** содержит и отложенные/неподходящие вакансии: доступен фильтр статуса.
- Исторические сообщения без достоверного времени показываются со временем импорта. Автор сообщения не угадывается.

В карточке сохраняются сопроводительное и имя резюме, если они были записаны при отправке. При отсутствии имени файла показывается «Версия в журнале не указана»: актуальный PDF не выдаётся за исторически отправленный.

## Запись будущих действий

Команда `node scripts/find-hh.cjs` параллельно читает первые страницы трёх поисков HH по удалённым вакансиям за 3 дня и сверяет ID с SQLite. Если свежие выдачи уже просмотрены, передайте `7` или `30`, чтобы расширить период. Например, `node scripts/find-hh.cjs 30 2` читает вторые страницы за месяц. Поле `unseen` содержит карточки для проверки требований. При сбое одного поиска команда показывает частичные результаты и возвращает ненулевой код.

Перед просмотром результатов поиска передайте ID одной площадки в `python3 manage.py unseen hh ID_1 ID_2 ID_3`. Команда возвращает JSON-массив новых ID в порядке выдачи. Для HH, Хабр Карьеры, getmatch и GeekJob она также учитывает подтверждённые отклики через компанию, если в журнале сохранена прямая ссылка на вакансию с этой площадки. Команда только читает базу. Уже известные вакансии проверяйте через очередь дашборда.

Для смешанной подборки прямых ссылок используйте `python3 manage.py unseen urls https://hh.ru/vacancy/123 https://career.habr.com/vacancies/456 https://getmatch.ru/vacancies/789`. Команда возвращает первую ссылку на каждую новую вакансию в исходном порядке. Региональные версии HH, параметры ссылок на поддерживаемые площадки и название вакансии после ID в ссылке getmatch не меняют ID.
Команда также принимает прямые ссылки с сайтов работодателей. Ссылку на карточку Ashby и её форму `/application` она сверяет как одну вакансию, в том числе после неподтверждённой отправки. Для остальных сайтов используйте ссылки на конкретные вакансии. Параметры и фрагменты URL учитываются при сравнении.

Для следующих сессий агента или скриптов есть единый вход:

```bash
python manage.py record \
  --platform hh --id REAL_VACANCY_ID \
  --title 'Frontend-разработчик' --company 'Компания' \
  --url 'https://hh.ru/vacancy/REAL_VACANCY_ID' \
  --status sent --evidence 'На странице показано «Вы откликнулись»' \
  --resume 'frontend-resume.pdf' \
  --cover-file /absolute/path/to/actual-sent-letter.txt
```

Это пример формата — не запускать как реальную запись. Использовать `sent` только после подтверждённой отправки; иначе `submitted_unconfirmed` или `needs_input`. Команда только записывает результат, не подаёт отклик. Записи дописываются с блокировкой файла в журнал текущего дня.

Существующие скрипты также могут продолжать писать текущие журналы — импорт совместим с ними. Поддерживаются `hh`, `habr`, `company`, `getmatch`, `geekjob`, `superjob`.

```bash
python manage.py import
python manage.py stats
python manage.py backup /absolute/path/career-backup.sqlite3
python -m unittest discover -s tests -v
```

## Структура

- `server.py` — локальный HTTP API, автоимпорт, запуск синхронизации HH.
- `store.py` — SQLite, объединение журналов, серверные фильтры, статистика и экспорт.
- `public/` — интерфейс без сборки и внешних CDN.
- `scripts/sync-hh.cjs` — чтение статусов HH через текущий браузер.
- `manage.py` — запись событий, импорт и резервная копия.
- `tests/` — проверка счётчиков, импорта, ручных изменений и экспорта.

## Тренажёр собеседований

Открывается на `http://127.0.0.1:4317/trainer` и из боковой навигации. База вопросов читается из `~/Documents/Career-template/interview-prep/question-bank.json`. Если своего файла ещё нет, доступны три стартовых вопроса из `training/question-bank.json`. Ответы и оценки сохраняются отдельно в `~/.local/share/career-template/trainer.sqlite3`.

Первый проход начинается с приоритетных вопросов. Самооценка 0–3 назначает повтор через 10 минут, 1, 3 или 7 дней. Просроченные повторения идут перед новыми вопросами. Доступны выбор темы и режим только повторений. Оценка текста автоматикой не выполняется.

Для резервной копии тренажёра нужно отдельно сохранить `trainer.sqlite3`: команда `manage.py backup` копирует только базу откликов.


## Codex: роли, навыки и флоу

Откройте корень своей копии в Codex как доверенный проект. Codex загружает проектные навыки из `.agents/skills/` и роли из `.codex/agents/`. Координатор ведёт путь от поиска до журнала и входящих. Для отдельных этапов есть исследователь, редактор, независимый проверяющий и тренер собеседований. [Рабочий флоу](career/WORKFLOW.md)

В терминале Codex начните с запроса: «Используй $career-search, прочитай профиль, найди несколько подходящих вакансий и подготовь черновики». Разрешение на отправку можете дать отдельно. Чтобы разобрать уже полученные ответы, используйте `$career-inbox`. Для подготовки к интервью используйте `$interview-training`.

Подготовьте свой профиль и подтверждения:

```bash
cp -n career/profile.example.json career/profile.json
cp -n career/evidence.example.json career/evidence.json
python3 career/scripts/career_memory.py context
```

Заполните личные копии профиля и подтверждений. Формат входных данных описан в [справке ATS](career/references/ats-input.md), финальная проверка CV — в [руководстве по preflight](career/references/preflight.md). Файлы профиля, подтверждений и базы памяти исключены из Git. Для загрузок, резюме и отчётов используйте папку вне репозитория или игнорируемую `private/`.


## Ponytail full и Playwright

Для работы над кодом шаблон использует правила Ponytail full из `AGENTS.md`. Чтобы подключить официальный плагин в своей версии Codex, проверьте поддержку `codex plugin --help` и выполните:

```bash
codex plugin marketplace add DietrichGebert/ponytail
codex plugin add ponytail@ponytail
```

Просмотрите hooks в `/hooks`, подтвердите доверие вручную и откройте новый тред. Для desktop перезапустите приложение. При необходимости выберите `/ponytail full`. [Официальная установка Ponytail](https://github.com/DietrichGebert/ponytail/blob/main/INSTALL.md)

Для HH, Telegram Web и браузерных тестов нужны Node.js 20+, npm и Playwright. Для чтения площадок запускайте выделенные профили Chromium с CDP только на localhost, затем войдите в свои аккаунты. Для тестов можно установить Chromium через Playwright (`npx playwright install chromium`) или указать путь к системному браузеру через `CAREER_CHROMIUM`.

```bash
npm ci
npx playwright install chromium
npm run check:hh
# В другом терминале запустите ./start.sh
npm run check:browser
```
