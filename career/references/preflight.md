# Строгая проверка резюме v0.2

Это локальный контроль качества, а не копия закрытого ATS работодателя. Он не вычисляет вероятность найма, не обещает обход фильтров и не разрешает внешнюю отправку.

## Вердикты

| Вердикт | Значение | Exit code |
|---|---|---|
| PASS_LOCAL | Все формализованные локальные проверки пройдены, есть актуальная независимая аттестация | 0 |
| REVIEW | Нужна смысловая проверка, есть пробел/неизвестное или не хватает финального review | 2 |
| BLOCKED | Есть неприемлемый документ/утверждение, недействительный источник или устаревший review | 3 |
| Ошибка выполнения | Не удалось прочитать/разобрать входы; не является прохождением | 4 |

REVIEW по требованию стажа не означает, что работодатель обязательно откажет. Это материал для честного решения по смежному опыту; скрипт сам не делает исключение и не подменяет факты. Даже PASS_LOCAL не отменяет паузу кампании.

## Запуск

```sh
python scripts/preflight.py \
  --vacancy private/preflight/vacancy.json \
  --resume private/resume-v3/react-ru.pdf \
  --claims private/preflight/claims.json \
  --review private/preflight/review.json \
  --output private/preflight/result
```

До финальной проверки аргумент review можно не указывать: результат будет REVIEW, остальные проверки всё равно выполнятся. По умолчанию читаются `career/profile.json` и `career/evidence.json`; альтернативные подтверждённые снимки можно явно передать через --profile/--evidence. Извлечение TXT/HTML/PDF/DOCX использует существующий career_ats.py. Для PDF нужен установленный pdftotext. В приватный output записываются report.json и resume-extracted.txt с правами0600; результаты внутри проекта разрешены только в `private/`.

## Вакансия

Вход — сохранённая исходная публикация, не рекламный пересказ. Поля: company, title, url, captured_at, text, requirements. Каждый requirement содержит уникальный id, kind, required(bool), source_quote. Цитата должна присутствовать в text. Обязательность и интерпретацию цитаты проверяет человек/агент-reviewer.

- skill: skill (ключ из profile.skills), basis=practice/commercial.
- experience: те же поля и min_months (целое неотрицательное). Общий frontend-стаж не React-стаж; срок Nuxt не выводить автоматически из Vue.
- condition: field=remote_from_russia/relocation/mandatory_office_visits и value(bool).

Неизвестные договор/выплаты/gross-net/география и прочие условия перечисляются в conditions_to_review. Они требуют REVIEW; не разрешать их пустым значением ради зелёного результата. Все остальные ограничения и скрытые вопросы анкеты проверяются отдельно.

## Карта утверждений

JSON: claims — массив, unresolved — список нерешённых вопросов. У утверждения id, text (точный фрагмент CV), evidence_ids, scope. Допустимые scope:

- commercial: достижение имеет хотя бы одно подтверждение коммерческого опыта.
- personal: личный проект, не повышает коммерческий стаж.
- local_benchmark: text явно ограничивает замер как локальный; обязательны measurement_limits с условиями и границами.
- profile_fact: идентификация/образование/даты/условия из профиля. Вместо evidence_ids использовать profile_refs — JSON Pointer, например /experience/0 или /email. Существование указателя не доказывает правильность пересказа; это задача reviewer.

Валидатор проверяет наличие источника, область и совпадение text. Он не способен доказать, что произвольное число семантически следует из evidence-id. Поэтому claim_coverage и metric_boundaries — обязательные пункты независимого review всего CV, а не только отмеченных фрагментов. Типовые проценты/стрелки/задержки без карты дополнительно подсвечиваются; это ограниченная эвристика, не полный анализ всех метрик.

## Финальный review

Файл review создаёт реально независимый проверяющий после чтения входов и визуального просмотра финального PDF:

- hashes: точные SHA256 vacancy/resume/profile/evidence/claims из последнего report.json.
- reviewed_by: идентификатор проверявшего.
- independent=true, verdict=approved.
- checks: claim_coverage, chronology, metric_boundaries, requirement_interpretation, visual_readability, recipient, conditions — все true только после фактической проверки.
- open_findings: пустой список только после устранения замечаний.

Каждый вход читается в снимок; SHA и извлечённый текст относятся к одним байтам. Изменение исходных файлов во время проверки даёт BLOCKED. Перед отправкой координатор всё равно сверяет hash фактически прикрепляемого файла: отчёт не блокирует будущие изменения файла.

Любое изменение перечисленных входов делает review устаревшим. Файл — аттестация, не криптографическое доказательство независимости. Не генерировать approved автоматически и не ослаблять проверки ради PASS_LOCAL. Для исследования без итогового CV нормально оставить REVIEW.

## Ограничения и источники правил

Ошибка извлечения не обязательно равна отказу внешней ATS. Визуальная вёрстка, скрытый текст, синонимы, отрицания и смысл бизнес-метрик требуют отдельной проверки. Универсального «идеального формата» и числа ключей нет. Счётчик пройденных локальных условий не выдаётся за работодателев балл.
